## Focus

Introduction to retrieval-augmented generation and the difference between a standard chatbot and a solution that works with its own documents.

## What We Worked On

- worked with RAG as an architecture
- compared different platforms for document-based chatbots
- used source documents as the data foundation
- evaluated quality, flexibility, and usability

## Key Concepts

RAG was treated as a way to connect a language model to a limited source foundation. The point is that answers should be grounded in actual sources rather than only in the model's general knowledge.

The material emphasized that data quality and source format matter a lot. Markdown was highlighted as a better format than heavy PDF, Word, or PowerPoint files because the content is usually easier to structure and retrieve.

There was also a focus on when RAG creates value, especially when a system needs to answer based on rules, documents, or domain-specific knowledge.

## Practical Notes

Three platforms were used as comparison points:

- ChatGPT Custom GPT for quick no-code setup
- CustomGPT.ai for a stronger focus on retrieval and citations
- Dify.ai for flexible prompting, debugging, and API access

An important working principle was to keep the data foundation small, relevant, and up to date.

## Key Takeaways

- RAG is just as much about sources and scope as it is about the model itself
- good answers require relevant documents and solid structure
- citations and traceability matter if the solution is to be used academically or professionally
